# Production-generation acceptance matrix

Status: acceptance design only, 2026-10-27. This completes the Phase 1 specification-to-test mapping, not implementation or product qualification. **Every acceptance evidence slot is PENDING. No tests, builds, migrations, native operations or live journeys were performed for this document.**

## Contract and evidence conventions

Authority: approved `spec.md` (all sections), `plan.md`, closed `audit.md`, and `targeted-inspections.md`. The audits are historical source assessments, not acceptance evidence; unresolved details below are concrete implementation/test obligations, not a reopened inventory. Implementation areas are intended change/test seams from those documents, not newly verified source findings.

- **U / I / T** mean proposed unit, integration and compiled ordinary-terminal checks. Every row specifies all three. T uses the real production host/worker/CLI composition and terminal entrypoint, not a reduced fixture host. Rows about internals require observable terminal outcomes plus fixture-side invariant assertions; terminal output alone cannot prove authority or durability.
- All automated checks use private short runtime roots, explicit isolated authoritative paths, bounded subprocess lifetimes and cleanup of test-owned children only. Use disposable database fixtures/copies and protocol-faithful loopback services. Never open live stores, installed launchers or native credentials. HOME isolation is not Keychain isolation.
- Production composition must remain unchanged by fixture injection. Credential-enabled scopes inject memory stores and fake transports into **every** child, with native-opener traps and child-environment assertions and positive fake-backend controls. Label artifacts using compile-time synthetic providers or injected credentials; do not describe them as unmodified production qualification.
- Each `E-xx PENDING` slot must eventually record exact candidate/source SHA, binary/build identity and manifests, commands, fixture mode, outcomes, assertions/artifact locations, skips, race coverage and uninstrumented children, platform and limitations. Keep secrets, message contents and sensitive backup copies out of git/reports. Failed persistence cannot be recorded as successful application merely because an RPC or log says success.
- Qualification codes in the final column: **Q0** = isolated automated evidence only, no live-cutover/platform-native claim; initial native target is macOS, other platforms require regression coverage and their own coexistence evidence. **QC** = Q0 plus separate authorization/evidence required for native credential backend and real issuer/provider activity (no spending authorized). **QM** = Q0 plus separate authorization/evidence required for actual runtime variants and real loaded-model/resource behavior; synthetic holds do not qualify real inference. **QX** = Q0 plus external integration/platform variants or exclusive-server behavior require explicit coverage, not assumptions. **QL** = live effect blocked until fresh, specifically scoped authorization. Codes combine; none makes pending work optional.
